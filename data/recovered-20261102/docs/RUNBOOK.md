# 离线检查与后续操作

## 已准备的最小动作

在本包根目录运行 tests。离线测试使用临时 SQLite、明确合成的样例，不访问行情接口、不留下数据库。原 catalog 测试只检查汇总逻辑，不能证明原数据还在。

`schema/001*` 是历史 SQLite 原 SQL。`schema/002*` 是新的 SQLite 设计。它们是独立用途；不要把 002 描述为生产数据库迁移。空库建表通过不代表采集、入库或回测通过。

## 如以后恢复采集

先选定来源、日期、股票池和存储根目录，确认供应商条款、所需输入和同一队列没有其他写入者。保留旧快照，在新工作目录建立新批次。逐个检查入口参数及顶层代码，不导入所有 Python 文件。核查依赖，不能把历史 runtime-dependencies.json 当完整 lockfile。遇401/403、验证码或明确拒绝，停止该路径，不改身份或代理。

## 如以后发布 GitHub

建议新增独立分支与目录，基于已验证的远端 main 最新版本，只加入本包白名单。不要基于无 remote、且有未提交更改的旧本地 Skill 快照直接推送。上传前重新检查 .gitignore、git diff、文件大小与凭据扫描；不覆盖既有 Skill。仓库 main 已有 ingestion.py、sources/baostock.py、tests/test_ingestion.py 和数据准备说明，相同哈希不再复制。

本包创建时没有 commit、push、PR、安装、网络采集或外部状态更改。
